# 人机协作范式·符合性自检清单

版本：v1.0  
状态：自检工具 · 从属于宪法 · v1.0 经所有者审阅确认，作为交付前自检依据  
上级文件：`HUMAN_AGENT_PARADIGM.md` v1.0（宪法）  
配套文件：`DERIVED_SPECIFICATION.md` v1.0（派生规范）

## 使用说明

1. **执行时机**：每次交付前（P7 前）、每个里程碑结束、每次治理审计时执行；交付前检查为强制项。
2. **判定方式**：每项只能填 `符合` / `不符合` / `不适用`。填 `符合` 必须填写证据 ID 或证据位置；填 `不适用`
   必须写理由；无证据的“符合”一律视为 `不符合`。
3. **★ 为硬性项**：任何一项 ★ 不通过，交付不得进入验收；涉及宪法 3.1、3.2、3.4 的不符合项，交付判定无效。★
   项不得填“不适用”；确有范围争议时，须回到契约流程由人裁决，而不是在本表内豁免。
4. **本清单是自检工具，不是符合性证明**：符合性最终以行为与结果、以可独立复核的证据为准（宪法 9.2）。自检通过不能替代多视角审视与人的验收。
5. **整改规则**：非 ★ 项不符合，必须记录缺陷、整改并复检；复检结果附在本表后，连同证据归档。
6. **签署**：检查人、检查时间、所用证据包版本必须记录；最终结论由人确认。

## 最终判定

| 项目                                 | 内容                                                                      |
|:-------------------------------------|:--------------------------------------------------------------------------|
| 检查人 / 检查时间                    |                                                                           |
| 证据包版本                           |                                                                           |
| 硬性项（★）总数 / 通过数            |                                                                           |
| 非硬性项总数 / 通过数 / 不适用数     |                                                                           |
| 范式级 J 组（本次是否适用 / 通过数） |                                                                           |
| 未关闭不符合项                       |                                                                           |
| 最终结论                             | `通过`（所有适用项符合且证据齐全） / `不通过`（任一 ★ 不符合或证据缺失） |
| 人确认签署                           |                                                                           |

**门槛规则**：

1. 任一 ★ 项不符合或证据缺失 → 最终结论为 `不通过`，不得进入验收。
2. 非 ★ 项不符合 → 记录、整改并复检；复检仍不符合的，本表不得判“通过”，必须回到契约流程：由人决定重开 P3
   调整范围/标准、显式接受为残余风险并记录，或终止；禁止静默放行。
3. “不适用”仅允许非 ★ 项，且必须写明理由；理由不足视为 `不符合`。
4. 本表任何“通过”都不能替代宪法 9.2 所要求的独立复核；最终符合性以行为和结果为准。
5. 若本次宣称“本范式已被实现”或进行范式级审计，J1–J7 必须全部通过并附证据；仅作单次产品交付的，J 组注明“本次不适用（仅产品交付）”。
